# NegQuote 预研报告：否定感知的引语支持性门控（v0.1）

> 性质：预研实验（preresearch）。新构造合成探针语料（`run_negquote.py` 内嵌，发布即冻结），
> 不是 CMRC2018，不是人工标注的自然背景，不是第三方认证。本实验不改冻结评测结论、不改 vendor 库。
> 运行：`py -3.13 run_negquote.py` → `negquote_results.json`。

## 一、动机

外部公开数据评测（`evaluation/评测报告.md`）已如实记录：在真实 CMRC 引语中加入"并非"类否定词后，
Gewita 仍给出 NEAR（近逐字）裁决——引语说了反话，报告却近乎逐字命中。文献共识（LLM 在否定
理解基准上接近随机、难以区分事实与其否定）说明语义层修复不可信，因此本预研选择**规则化降级**：
引语与原文片段出现"否定线索不对称"（引语含否定词、对齐片段不含）时，支持性裁决降级为
`UNSUPPORTED_PENDING_REVIEW`（待人工复核），不假装语义理解。

## 二、规则（冻结于运行前）

- 线索表 21 项（并非/并不/没有/未/无/非/不得/不含/未达/拒绝/禁止…，见 JSON `cues` 字段）。
- 适用等级：VERBATIM / NEAR / PARAPHRASE（有证据片段的裁决）；NOT_FOUND 无片段不适用。
- 触发条件：引语含线索 ∧ 片段不含 → 降级。线索对称（如原文自身"不得"被逐字引用）不触发。

## 三、结果（215 个探针）

| 探针组 | n | 门控触发 | 说明 |
|---|---:|---:|---|
| verbatim 逐字 | 45 | 0 | 无误报 |
| **near_negation 最小否定编辑（1–2 字）** | 40 | **39（97.5%）** | 唯一漏检："支持→不支持"型（线索表无"不支持"，见缺口） |
| numeric_perturbation 数字置换 | 40 | 2 | 非本门控目标类；2 次触发系引语偶含线索字（逐条见 JSON），行为符合规则定义 |
| paraphrase 换述（无否定） | 40 | 0 | 无误报 |
| fullwidth 全角变体 | 45 | 0 | 无误报 |
| control_neg 原文含否定的逐字引语 | 5 | 0 | 线索对称放行正确 |

## 四、诚实发现（含对本库不利的）

1. **在短句合成语料上，最小否定编辑即使没有门控也已降到 PARAPHRASE**（NEAR 现象出现在更长的
   真实引语上，与评测报告一致）。门控的增量价值是：把"引语含否定而片段不含"从词面重叠描述
   （PARAPHRASE 听起来像"换述"）升级为明确的待复核状态，覆盖 NEAR 与 PARAPHRASE 两级。
2. 线索表覆盖有缺口：裸"不"字否定（不支持/不存在）未收录——单"不"字噪声大，v1.0 需扩充为
   "不+动词"模式并重新在**新冻结集**上评测。
3. 未覆盖类：原文否定/引语肯定（本门控不对称方向的镜像）；数字置换等非否定反例（2 次触发属
   偶含线索字，规则行为正确但语义并非否定问题）。
4. 全部结果为合成语料上的行为描述；要主张生产可用性，需 ≥300 对真实背景引语 + 未参与开发者的
   人工复核（v1.0 计划）。

## 五、v0.3 路线图（不随本预研实施）

1. Gewita 增加 opt-in 门控参数（如 `--quote-gate strict`），默认关闭，不改变现有冻结行为。
2. v1.0 冻结协议：≥300 对真实背景引语最小对（含 5 种否定变换 × 3 种字符形态），
   报告触发率、漏检分布、逐线索误报与阈值敏感曲线；复核者须未参与开发。
3. 与 Siftan 联动：门控降级的引语进入人工复核队列时附污染筛查结果，形成复核工单。

### 修复内容（冻结于运行前）

- 新增线索 16 条（常用"不+动词"白名单）：不支持 / 不存在 / 不包含 / 不具备 / 不符合 /
  不满足 / 不达标 / 不同意 / 不允许 / 不接受 / 不属于 / 不合格 / 不通过 / 不成立 /
  不适用 / 不可行。
- 单"不"字与"不+名词/形容词"仍不收录（噪声大：不同/不断/不错等），模式化扩充留给 v1.0。
- 预注册预期（写于运行前）：near_negation 39→40；其余五组触发数不变。实际结果与预期一致。
